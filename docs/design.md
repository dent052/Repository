# 設計資料: 情報セキュリティマネジメント試験 学習システム

## 目的

情報セキュリティマネジメント試験（SG）に合格すること。利用者は 2026年12月に受験する。学習時間は通勤中と寝る前の各15分。

用語の一覧を読ませる体系テキストはやめた（「用語が多すぎて頭に入らない」「解説を読んでも覚えられない」「解く快感がなく続かない」という利用者の感想から）。代わりに、架空の会社の情報セキュリティ担当者として毎回「事件」に対応する物語の中で、過去問を中心に解く。間違えたら「決め手の1文」を読み、同じ論点の別の問題ですぐ取り返して「わかった」で終える。

経緯と判断の理由は `docs/superpowers/specs/2026-11-02-sg-incident-design.md` にある。

## 対象とする試験（2026年度まで実施の現行制度）

| 項目 | 内容 |
| --- | --- |
| 方式 | CBT、通年実施 |
| 試験時間 | 120分（科目A・科目Bを通しで解答） |
| 科目A | 48問、四肢択一、知識問題 |
| 科目B | 12問、多肢選択、事例（ケーススタディ）問題 |
| 合格基準 | 総合評価点 1,000点満点中 600点以上 |

- 出題範囲は IPA のシラバス Ver.4.1（用語例 911 語）に沿う。
- 科目Aの内訳は、セキュリティ 約30問・法務 約4問・その他（テクノロジ系／マネジメント系／ストラテジ系）約14問。
- 科目B 12問はすべて情報セキュリティ分野（情報資産管理、リスクアセスメント、物理的・技術的要求事項、システム利用時のセキュリティ、委託先管理、インシデント管理、意識向上、継続的改善）。
- 2027年度から試験制度の見直しが予定されている。新制度に切り替わったら本資料と問題を見直す。

## 出典について

- 科目A・科目Bの問題、全ての解説、話の物語と決め手の1文は、本リポジトリで書き起こしたオリジナルである。出題傾向（頻出テーマ、問われ方、難易度）だけを参考にし、過去問の文章は使わない。
- これとは別に、IPA が公表している過去問題を「過去問演習」として収録する（下記「過去問演習」）。
- 参考にした資料:
  - シラバス Ver.4.1 の用語例（情報セキュリティマネジメント試験ドットコム sg-siken.com の用語集で分野別に確認）
  - 新制度（2023年4月〜）の公開問題: サンプル問題、令和5〜8年度公開問題（sg-siken.com で確認）

## 学習の流れ

```
ホーム ─ [後始末（今日の復習）] ─ [次の話] ─ [事件ファイル] ─ [模擬試験]
```

### 世界観

- 利用者は架空の部品メーカー「みなと精工」（従業員約300人）に着任した新任の情報セキュリティ担当者。
- 登場人物: 柴田部長（情報セキュリティ責任者、利用者の上司）、システム部の三浦さん、総務の岡本さん、営業の高木さん。
- 既存の作品の世界観・名称は使わない。

### 1話（通勤中の15分）

詳しい経緯は `docs/superpowers/specs/2026-11-03-sg-talk-redesign.md`。

```
場面1（会話）→ 場面2 →［略語の組み立て］→ 問題 3〜5問 → 場面3 → 問題 3〜5問（前の場面の論点も混ぜる）→ 結末
```

1. **場面**: 登場人物の会話と地の文（顔の絵はなく、名前だけ）。行はタップせずに上から 0.12秒ずつ自動で現れ、スクロールして自分のペースで読む。覚えどころは黄色の下線（`<mark>`）。
2. **問題**: 本番形式の4択（科目Bは本番どおりの選択肢数）で、過去問と本番レベルの問題だけを出す。○× や易しい確認問題は出さない。
   - 問題に出る論点は、必ずそれより前の場面で教えておく。場面の直後にそのまま聞かず、場面を読んだあとに順番を混ぜて、本番の言い回しで聞く。
   - **ヒント**: 「カギにヒントをもらう」で、その論点を教えた場面の覚えどころの行を出す（答えの選択肢は出さない）。使うとその問題の XP が半分。
   - 解答後は、判定、決め手の1文、解説の全文を下から出る欄に出す。
   - 不正解のとき、同じ論点の別の問題（**取り返し問題**）を次に差し込む。選び方は (1) どの話にも入っていない未解答の問題 (2) どの話にも入っていない問題 (3) 未解答の問題 (4) それ以外、の順。同じ話ですでに出した問題は使わない。候補がなければ差し込まない。取り返し問題で間違えても、さらに差し込むことはしない。
3. **略語の組み立て**（話に指定がある場合）: 略語の1文字ずつに、正しい英単語を3つの候補から選ぶ。外れの候補は、用語集の他の正式名称の単語のうち同じ頭文字のもの。間違えても減点しない。終わると +10 XP。
4. **結末**: 話の本来の問題の1回目の正答率で、3段階の結末（0.8以上／0.5以上／それ未満）から1つを出す。取り返し問題の結果は結末に入れない。正答率・最高連続・XP、「今日わかるようになったこと」（最大3つ）、会社の安全度の変化を出す。
- 手順を1つ進めるごとに保存し、途中で閉じても次に開くと続き（取り返し問題を含む同じ手順）から始まる。
- 1日に進める話の数は制限しない。

### カギ（マスコット）

- 南京錠に顔を付けたマスコット。問題画面の右上、判定の欄、結末に出る（会話の場面には出さない）。
- 待機: 呼吸とまばたき。正解: 跳ねて錠の輪が閉まり、きらめく。不正解: 錠の輪が外れて揺れ、汗。ヒント: 目を見開いて小さく跳ねる。

### 後始末（寝る前の15分）

- 間隔反復で今日が復習日になっている問題を、最大15問出す。解答の表示は話と同じ（論点のない問題は解説をそのまま出す）。

### 事件ファイル

- 解決した話の一覧。開くと、その話の論点の決め手の1文が読める。

### 話の数と公開

- 予定は30話（`PLANNED_EPISODES`）。第1〜14話を公開している（2026-11-03）。学習の進みより先回りして足していく。
- 順序: 脅威・攻撃 → 認証・暗号 → 技術的対策 → リスクマネジメント・ISMS → インシデント対応 → 法務 → テクノロジ・マネジメント系 → 科目B中心の総まとめ。
- 後半の話では最後に科目Bの事例問題を1問出し、解答後に判断の決め手になる文を目立たせる（その話を作るときに決める）。

## 決め手の1文（論点）

- 各問題は論点を1つ持つ。論点ごとに決め手の1文（`hook`）を持ち、同じ論点の問題は同じ1文を共有する。
- 1〜2文、80字程度まで（100字を超えない）。定義の羅列にせず、**目印**（何を見たらその用語だと分かるか）か、**違いはここだけ**（紛らわしい相手と分ける軸）の形で書く。
- 正しさは Codex のレビューで確かめる（実装は Claude、レビューは Codex）。

## 過去問演習

- IPA が公表している情報セキュリティマネジメント試験の過去問題を収録する。IPA は、教育目的で問題集などに使う場合、許諾も使用料も不要としている（試験制度に関するよくある質問「その他」）。その留意点に従う。
  - 問題ごとに出典を表示する。例:「出典：令和8年度 情報セキュリティマネジメント試験 公開問題 問1」
  - 図を文章や表に置き換えるなど、問題の一部を改変した場合は「（一部改変）」と表示する。
  - 正解は IPA の解答例に従う。解説は IPA が公表していないので、本リポジトリで書く（解説の書き方は「難易度」の解説の項と同じ）。
- 収録する回:
  - 新制度の公開問題: 令和5〜8年度（各15問。科目Aと科目Bを含む）
  - 旧制度の午前試験: 平成28年度春期〜令和元年度秋期（各50問。今の科目Aと同じ形式）
- 旧制度の問題は、その後の法改正や規格の改訂で現在の正解と食い違うことがある。正解が変わる問題は収録しない。正解は変わらないが用語や規格名が古い問題は、解説でその旨を書く。
- 過去問は本番の問題そのものなので、話の問題の中心にする。後始末（復習）と合格予測メーターに含める（章は内容から 1〜10 に割り当てる）。模擬試験はオリジナル問題だけで組む。過去問を回ごとに解く画面は持たない。

## 続けるための仕組み

### 間隔反復（後始末）

- 一度でも解いた問題は、正誤に応じて次に出す日（復習日）を決める。今日以前が復習日の問題が「後始末」に並ぶ。話・後始末・模擬試験のどこで解いても記録する（取り返し問題も含む）。
- 問題ごとに習熟段階 `box`（0〜5）を持つ。正解で1段上げ（最大5）、不正解で0に戻す。次の復習日は「今日 + 間隔[box]」日後。

| box | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 次の復習までの日数 | 1 | 1 | 3 | 7 | 14 | 30 |

- 日付は端末の現地日付（YYYY-MM-DD）で扱う。
- **自信なし**: 話・後始末で正解したあと「🤔 自信なし」を押すと、正解として記録したまま、習熟段階を0に戻して翌日の復習に入れる（不正解のときは元から翌日に入るので、ボタンは出さない）。勘で当たった問題を、次回もう一度確かめるため。

### 会社の安全度（合格予測メーター）

- 物語の上では「会社の安全度」と呼ぶ。科目A・科目B・過去問の全問題の結果で計算する。
- 章ごとの実力 ＝ 直近の解答が正解の問題数 ÷（解いた問題数 ＋ 5）。解いた数が少ないうちは低めに出る（＋5 は少数の結果で高く出すぎないための補正）。
- 予測点 ＝ 1000 × Σ（章の出題数 × 章の実力）÷ 60。章の出題数は模擬試験と同じ（章1〜9は「模擬試験の出題」の表、科目Bは12）。
- 600点の合格ラインとの差を表示する。

### 連続日数

- 1問でも解いた日を「学習した日」として記録する。
- 今日まで（今日がまだなら昨日まで）続けて学習した日数を連続日数とする。
- 1日だけの休みは、7日に1回まで許して連続を途切れさせない（休んだ日は日数に数えない）。

### 試験日カウントダウン

- 試験日を設定すると、残り日数と「1日あたりの目安 ＝ 残りの話数（予定の30話のうちまだ解決していない数）÷ 残り日数（切り上げ）」を表示する。後始末はこれとは別に行う。

### 演出と見た目

- 演出は「めったに起きないことほど大きく」。
  - 選択肢を押す: 0.09秒で 97% に沈む。
  - 正解: 振動 15ms、選んだ選択肢が跳ね、「+XP」が上の XP まで飛んでから数え上がる。
  - 不正解: 振動 40-60-40ms、選んだ選択肢が左右に揺れる。
  - 連続正解: 3問から「◯重ロック」を表示。5問・10問で大きく弾んで振動。5問以上は XP 2倍。
  - 結末: カギ → 題 → 結末の文 → 数字の数え上げ、の順に見せる（ここだけ大きく）。
- 音は入れない。`prefers-reduced-motion` が有効なら動きを全て止める。
- 色: 背景 `#FBFBF9`、文字 `#2E333D`、操作 `#0F6E6E`、正解 `#2E9E5B`、不正解 `#D64545`、覚えどころ `#FFE28A`、カギ `#FFD66B`。書体: 会話と画面は Zen Maru Gothic、問題文と選択肢は Zen Kaku Gothic New。影・グラデーション・絵文字の多用はしない。

## 用語集（タップで意味を表示）

- `web/data/glossary.js` に、用語と一言の説明（80字以内）を持つ。
- 英字の略語（例: SPF、IoT、SaaS、DNSキャッシュポイズニングの DNS）を含む用語は、何の頭文字かが分かるように正式名称 `en` も持ち、説明の上に表示する（例: “Sender Policy Framework”。略語が用語の一部なら “DNS = Domain Name System”）。`test/data.test.js` で確認する。
- **略語の分解**: 略語そのものが用語の場合（例: SPF）、正式名称の単語ごとに頭文字を強調して並べる。単語ごとの日本語 `ja`（`en` を空白で区切った単語と同じ数）があれば各単語の下に出す。話の場面に出てくる略語には `ja` を付ける。
- 話の場面・決め手の1文・問題文・解説の中で、用語集にある語に点線の下線を付け、タップすると画面下に意味を表示する。
  - 同じ画面では、それぞれの用語の最初の1か所だけに付ける（下線だらけにしない）。
  - 見出し・表の見出しと1列目・ボタンの中には付けない。
  - 長い用語を優先して照合する（例:「DNSキャッシュポイズニング」を「DNS」より先に）。英字やカタカナの用語は、前後が同じ種類の文字の場合は照合しない（例: “IPS” を “IPsec” の中で、「ログ」を「プログラム」の中で拾わない）。

## 採点

- 1問の配点は均等とし、`正解数 / 出題数 × 1000` を得点（目安）とする。600点以上を合格目安とする。
- 本番は IRT による採点で配点は非公開のため、あくまで目安である。

## 模擬試験の出題

- 科目A 48問は、本番の内訳（セキュリティ30・法務4・その他14）に合わせて章ごとの固定数を、本番レベルの問題からランダムに出す。

| 章 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 計 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 出題数 | 5 | 5 | 5 | 5 | 5 | 5 | 4 | 5 | 9 | 48 |

- 第8章（ネットワーク・DB・システム構成）は本番の「その他」のうちテクノロジ系、第9章（監査・サービス・プロジェクト・戦略・企画・企業活動）はマネジメント系とストラテジ系に当たる。
- 科目B 12問は科目B問題からランダムに出す。科目B問題は模擬試験8回分（96問）以上を用意し、本番と同じ「解答群から組合せを選ぶ」10択の問題も含める。

## 問題数の目安

- 科目Aは各章とも模擬試験の出題数の3回分以上。
- 追加するときは、配点の大きいセキュリティ（章1〜6）と法務（章7）を優先し、まだ問題で問われていないシラバスの頻出用語から作る。
- 正解の位置（ア〜エ）は偏らないようにする（各15%以上）。

## 難易度

- 問題は全て本番レベルにする（基礎レベルの問題は持たない）。
- **本番レベルの条件**: 用語や論点を知らないと、選択肢だけを見て消去法で解けないこと。
  - 誤答は「実在する別の概念の説明」「正解と紛らわしい用語」「一部だけ誤った記述」にする。常識で誤りと分かる選択肢（「パスワードを紙に書いて貼る」「全員の PC の電源を切る」など）は使わない。
  - 選択肢の長さで正解が分からないようにする。正解が4つの中で唯一いちばん長い問題は、本番レベルの問題の3割以下にする（`test/data.test.js` で確認）。
  - 本番でよく出る形も取り入れる: 定義を入れ替えた4つの説明から正しいものを選ぶ、規格の用語の定義を選ぶ、計算、条件を当てはめる問題。
- **解説**: 正解の根拠に加えて、紛らわしい誤答がそれぞれ何の説明（どの用語）かを短く書く。選択肢にない内容に触れたり、選択肢と食い違ったりしないこと。選択肢を変えたら解説も合わせて直す。長さは 200 字程度までを目安にする。
- **科目Bの事例文**: 本番と同じく、状況を読み取って判断させる長さにする。タグを除いた本文で 800〜1,500 字（`test/data.test.js` で確認）。
  - 組織の概要、関係者と役割、規程や手順（表）、出来事の経緯を書く。答えに関係しない事実も混ぜ、どの情報が判断に効くかを読み取らせる。
  - 誤りの選択肢は、事例の一部の事実だけを見ると正しく見えるものにする。

## データ形式

問題（科目A・科目B共通）:

```js
{
  id: "a3-05",          // 一意。科目Aは "a<章>-<連番>"、科目Bは "b-<連番>"
  chapter: 3,           // 科目Bは 10
  scenario: "<p>…</p>", // 科目Bの事例文（HTML）。科目Aでは省略
  question: "…",        // 設問（HTML可）
  choices: ["…", "…"],  // 科目Aは4つ、科目Bは4〜10個
  answer: 0,            // 正解の choices の添字
  explanation: "…",     // 解説（HTML可）
}
```

過去問（`web/data/questions-past.js`）:

```js
// 回の一覧
{ key: "r08", title: "令和8年度 情報セキュリティマネジメント試験 公開問題" }
// 問題（上の問題の項目に加えて）
{
  id: "p-r08-01",       // 一意。"p-<回>-<問番号2桁>"
  exam: "r08",          // 回の key
  no: 1,                // 問番号
  modified: true,       // 一部改変した場合だけ付ける
  chapter: 3, scenario, question, choices, answer, explanation, // 意味は上と同じ
}
```

論点（`web/data/points.js`）:

```js
{
  id: "virus-worm-trojan",                  // 一意
  title: "ウイルス・ワーム・トロイの木馬",
  hook: "違いは「寄生するか・自分で増えるか」。…", // 決め手の1文（100字以内）
  questions: ["p-h29a-27", "a2-15", "a2-16"], // この論点の問題。1つの問題は1つの論点にだけ入る
}
```

話（`web/data/episodes.js`）:

```js
export const PLANNED_EPISODES = 30;
{
  no: 1,                                    // 1 からの連番
  title: "社長を名乗るメール",
  steps: [                                  // 出す順
    { scene: { title: "振込先が変わりました", points: ["bec"],        // 場面。points はこの場面で教える論点
      lines: [["n", "地の文"], ["s", "セリフ。<mark>覚えどころ</mark>"]] } }, // n=地の文 s=柴田部長 o=岡本さん m=三浦さん t=高木さん
    { game: "DKIM" },                       // 略語の組み立て（任意）
    "p-r01a-01",                            // 問題 ID。8〜12問。全て論点に入り、話の間で重複せず、その論点はより前の場面の points にある
  ],
  endings: ["…", "…", "…"],                 // 正答率 0.8以上 / 0.5以上 / それ未満 の結末
}
```

## 進捗の保存

```js
{
  stats:  { "a3-05": { c: 2, w: 1, last: true, box: 2, due: "2026-10-10" } }, // 正解数・不正解数・直近の正誤・習熟段階・次の復習日
  exams:  [ { date: "2026-10-07T10:00:00.000Z", score: 650 } ], // 模擬試験の記録（直近20回まで）
  days:   ["2026-10-06", "2026-10-07"],     // 学習した日（直近400日まで）
  examDate: "2026-12-01",                   // 試験日（未設定なら null）
  ep: {
    next: 3,                                // 次に始める話の番号
    results: { "1": 0.8, "2": 0.6 },        // 解決した話の正答率

  }
}
```

- まずブラウザの localStorage に保存する。
- claude.ai の Artifact として開いた場合は、`db` 機能が使えればログイン中の本人専用領域（`data/users/<id>/progress/main`）にも保存し、端末をまたいで進捗を引き継ぐ。
- db への書き込みは1件ずつ行い、書き込み中に発生した変更は次の1回にまとめる（同時書き込みをしない）。
- 話・後始末では1問ごとに正誤を記録する。模擬試験は終了時にまとめて記録する。

## 1ファイル版（オフライン利用）

- `npm run build` で、HTML・CSS・JS・問題データを1つの HTML ファイル `dist/sg-trainer.html` にまとめる。
- ES モジュールはローカルファイル（file://）から読み込めないため、`import` / `export` を取り除いて1つの通常の `<script>` に連結する。連結順は core.js → data（問題 → 用語集 → 論点 → 話）→ app.js。
- このファイルをスマートフォンや PC に保存すれば、サーバーなしでブラウザで直接開け、オフラインでも使える（Webフォントだけはオンライン時のみ。オフラインでは端末のフォントで表示する）。
- 進捗はそのブラウザの localStorage に保存する。claude.ai の Artifact もこの1ファイル版を公開する。

## アイコン

- アプリのアイコンは `web/icon.svg`（紫からピンクのグラデーションに、白い盾とチェックマーク）。主な絵柄は中央の安全領域（直径80%の円）に収め、ランチャーが丸や角丸に切り抜いても欠けないようにする（maskable）。
- `web/icon-192.png` と `web/icon-512.png` は icon.svg から作った PNG。
- 1ファイル版では 192px の PNG を data URI として HTML に埋め込む。ただし Android の Chrome は、端末内のファイルから追加したショートカットにはページのアイコンを使わないため、ホーム画面に置くならインストール版（下記）を使う。

## インストール版（PWA、GitHub Pages で公開）

- `web/` をそのまま GitHub Pages の `gh-pages` ブランチで公開する。URL は https://dent052.github.io/Repository/ 。
- `web/manifest.webmanifest` で名前・アイコン・テーマ色を定め、`display: standalone` で URL 欄のない全画面で起動する。
- `web/sw.js`（Service Worker）で、アプリのファイルを端末に保存してオフラインでも開けるようにする。
  - 取得はネットワーク優先: オンラインなら常に最新を取りに行って保存し直し、オフラインなら保存済みのものを返す。更新のたびにキャッシュ名を変える必要がない。
  - 保存するのはアプリ自身のファイル（同じオリジンの GET）だけ。対象は決まった数のファイルなので、キャッシュは増え続けない。
- Service Worker は manifest のリンクがあるページ（インストール版）でだけ登録する。1ファイル版と Artifact では manifest のリンクを取り除くので登録しない。
- 公開は `npm run deploy`（`web/` を `gh-pages` ブランチにプッシュする）。初回だけ、リポジトリの Settings → Pages で「Deploy from a branch」「gh-pages」「/ (root)」を選ぶ。
- 進捗はインストール版のブラウザ領域に保存され、1ファイル版や Artifact とは別になる。
