# Claude と Codex の自動連携

対象: `dent052/Repository` / 既定ブランチ: `master`

Claude に実装を依頼すると、Claude が作業ブランチを保存して PR を作成します。
Codex が PR を自動レビューし、Claude のクラウドルーティンが未対応の指摘を調べ、
必要な修正を同じ PR に保存します。更新後の Codex レビューも自動実行するよう設定します。
人が毎回レビュー内容をコピーしたり、別の AI に続きを依頼したりする必要を減らします。

## 初回だけ行う設定

この設定案を `master` に取り込んだ後、以下の 2 つを設定してください。
ファイルを置くだけではクラウドサービス側の自動実行は有効になりません。

### 1. Codex の自動レビュー

[Codex のコードレビュー設定](https://app.chatgpt.com/settings/code-review)で
`dent052/Repository` の Automatic review を有効にします。
対象はこのリポジトリのすべての PR にし、Review trigger は PR の作成と
新しいコミットの追加時にレビューする設定を選びます。
Personal preferences にも Automatic review がある場合は有効にしてください。
画面の名称が変わっている場合は、PR の作成・更新時に自動レビューする設定を選びます。

既存の [PR #2](https://github.com/dent052/Repository/pull/2) には、手動のレビュー依頼が投稿されています。
設定後にその PR のレビューを一度依頼するか、次の新しい PR で動作確認してください。
設定確認時点では PR #2 にレビュー投稿はなく、自動レビューの稼働は未確認です。

### 2. Claude の修正ルーティン

[Claude の Routines](https://claude.ai/code/routines)で New routine を選びます。

- 名前: `Codex の指摘を自動修正`
- リポジトリ: `dent052/Repository`
- Instructions: [claude-routine-prompt.md](claude-routine-prompt.md) のコードブロック内をコピー
- 環境: このプロジェクトで使っているクラウド環境
- Trigger: Schedule / 毎時（指定できれば毎時 07 分）
- Connectors: この作業に必要な GitHub 連携だけを選択

Create で保存し、Run now で一度確認してください。
ルーティンは毎回新しいクラウドセッションで動き、元のチャットが閉じていても実行されます。
アカウント側で Routines が使えること、GitHub の PR・レビューの読み取りと
作業ブランチへの保存ができることが必要です。

## 設定後の使い方

Claude に作りたい機能を依頼するだけです。リポジトリの `CLAUDE.md` に従い、
実装後は PR 作成まで行います。その後のレビューと修正はクラウド上で進みます。
結果は GitHub の PR と Claude の Routines の実行履歴で確認できます。

- 対象は `dent052` が作成した、このリポジトリ内の `claude/` ブランチから `master` への通常の PR。
- Codex の指摘から修正開始までは通常約 1 時間以内。サービスの遅延・利用上限で遅れる場合があります。
- 指摘を採用するかは Claude が判断し、見送る場合は理由を記録します。
- 修正ルーティンには PR ごとに最大 3 回の処理を指示し、結論が出ない場合は人に引き継ぎます。
- PR の取り込みはこの自動化の対象に含めていません。
- 通常の Claude Auto-fix と併用すると同じ PR を同時に編集する可能性があるため、この方式ではルーティンを修正担当にします。
- コードは GitHub 経由で共有されます。元の会話履歴を別の AI に転送する仕組みではありません。
- 定期実行は利用枠を消費します。停止する場合は Routines のスイッチをオフにします。

## 動作確認

1. Claude に小さな実装を依頼し、通常の PR が作成されることを確認する。
2. 新規 PR に Codex のレビューが自動投稿されることを確認する。
3. ルーティンの Run now または次の定期実行で、未対応の指摘が処理されることを確認する。
4. 修正された場合は、同じ PR に新しいコミットが追加され、Codex が再レビューすることを確認する。
5. 再実行して、処理済みのレビューが重複処理されないことを確認する。

現在のリポジトリには実装やテスト基盤がなく、この変更は作業ルールと設定手順です。
サービス側の設定と実際のレビュー・修正を通した動作確認は、初回設定後に行います。
