# 設計: 会話で教えてから本番の4択を解く形へ（試作1〜5の結論）

2026-11-03 作成。2026-11-02 の事件対応型（`2026-11-02-sg-incident-design.md`）を公開したあと、利用者が試作を5回触って決めた内容。実装前に `docs/design.md` をこの内容で直す。

## 利用者の指摘と結論

| 指摘 | 結論 |
| --- | --- |
| 予備知識がないのに物語の中で問題を出されても解けない | 問題の前に、会話の場面で教える。問題に出る論点は、必ずそれより前の場面で教える（データ検査で確かめる） |
| 直前に答えをそのまま見せてから聞くのは馬鹿にしている | 場面を2つほど読んでから、順番を混ぜて出す。場面の文をそのまま聞かず、本番の言い回しで聞く |
| 本番の問題は ○× ではない | 問題は全て本番形式の4択（科目Bは本番どおりの選択肢数）。○× は作らない |
| 試験に出そうもない簡単な設問は合格につながらない | 解かせるのは過去問と本番レベルの問題だけ |
| セリフを1行ずつタップするのはテンポが悪い | 場面の会話はまとめて表示し、上から自動で流して出す。スクロールして自分のペースで読む |
| 会話は良い。キャラクターの顔は要らない | 登場人物は名前だけ。顔の絵は描かない |
| 原色すぎる・AI っぽい・演出がださい | 落ち着いた配色。演出は「めったに起きないことほど大きく」。下記 |
| マスコットはいてもいい | 南京錠の「カギ」。反応とヒントを担当する |
| 英字の略語にとっかかりがない | 略語はタップで頭文字ごとに分解。場面のあとに組み立てるミニゲーム |

## 1話の流れ（約15分）

```
場面1（会話）→ 場面2 →［略語の組み立て］→ 問題 3〜5問 → 場面3 → 問題 3〜5問（前の場面の論点も混ぜる）→ 結末
```

- 場面: 3〜8行の会話と地の文。覚えどころは `<mark>` で示す（黄色の下線）。
- 問題: 本番形式の4択。解答後に判定・決め手の1文・解説の全文を出す。
- 間違えたら、同じ論点の取り返し問題を次に差し込む（今の仕組みのまま）。
- ヒント: 問題画面で「カギにヒントをもらう」を押すと、その論点を教えた場面の `<mark>` を含む行を出す。答えの選択肢は出さない。使うとその問題の XP が半分。

## カギ（マスコット）

南京錠に顔。丸い体・大きめの目・ほっぺ。状態ごとに動く:

| 状態 | 見た目と動き |
| --- | --- |
| 待機 | 呼吸（わずかに伸び縮み）とまばたき |
| 正解 | 跳ねて着地でつぶれ、錠の輪が「カチッ」と閉まる。きらめき |
| 不正解 | 錠の輪が外れて傾き、左右に揺れる。汗 |
| ヒント | 目を大きく見開き、小さく跳ねる |

置く場所は、問題画面の右上と判定の欄、話の結末。会話の場面には出さない。

## 演出

| 出来事 | 演出 |
| --- | --- |
| 選択肢を押す | 0.09秒で 97% に沈む |
| 正解 | 振動 15ms。選んだ選択肢が跳ね、「+20」が XP の数字まで飛んでから数え上がる。判定の欄が下から出る |
| 不正解 | 振動 40-60-40ms。選んだ選択肢が左右に 6px 揺れる |
| 連続正解 | 3問から「◯重ロック」を表示。5問・10問で大きく弾み、振動。5問以上は XP 2倍 |
| 話の結末 | ここだけ順番に見せる: カギ → 題 → 結末の文 → 正答率・最高連続・XP を数え上げ |
| 場面 | 会話の行が 0.12秒ずつ順に現れる |

- 動きを減らす設定（`prefers-reduced-motion`）では全て止める。音は入れない。

## 見た目

- 背景 `#FBFBF9`、文字 `#2E333D`、操作の色は深い青緑 `#0F6E6E`、正解 `#2E9E5B`、不正解 `#D64545`、覚えどころの黄 `#FFE28A`、カギの金 `#FFD66B`。
- 書体: 会話・画面は Zen Maru Gothic、問題文と選択肢は Zen Kaku Gothic New（本番に近い硬い書体）。
- カードの影・グラデーション・絵文字の多用はしない。押すボタンは下端に幅いっぱい、立体の縁取り。

## 略語の分解

- 用語集の英字の略語は全て正式名称 `en` を持っている（既存のデータ検査）。これを使う。
- 会話・問題文・解説の中の略語（用語集にある英字の略語）をタップすると、`en` の単語ごとに頭文字を強調して並べ、用語集の説明 `desc` を添える。
- 単語ごとの日本語訳 `ja`（`en` の単語と同じ数）があれば、各単語の下に出す。第1〜14話の場面に出る略語には `ja` を付ける。
- 組み立てミニゲーム: 話に `game: "DKIM"` のように指定すると、場面のあとに入る。1文字ずつ、正しい単語を3つの候補から選ぶ。外れの候補は、用語集の他の `en` の単語のうち同じ頭文字のものから選ぶ。間違えても減点しない。終わると +10 XP。

## データ

```js
// web/data/episodes.js
{
  no: 1, title: "社長を名乗るメール",
  steps: [
    { scene: { title: "振込先が変わりました", points: ["bec"], lines: [["n", "地の文"], ["o", "セリフ（<mark>覚えどころ</mark>）"]] } },
    { game: "DKIM" },
    "p-r01a-01",             // 問題 ID
  ],
  endings: ["…", "…", "…"],
}
// 話す人: n = 地の文、s = 柴田部長、o = 岡本さん、m = 三浦さん、t = 高木さん
```

- 話の問題は `steps` の中の問題 ID。データ検査: 問題は全て論点に入る／話の間で重複しない／**問題の論点は、それより前の場面の `points` に入っている**／場面の `points` は存在する／場面には `<mark>` が1つ以上ある。
- 用語集の略語: `ja` は `en` を空白で区切った単語の数と同じ数。

## 進捗

- `ep.cur` は `{ no, seq, i, follow, first, learned, before }`。`seq` は話の手順を並べたもの（`"s:0"` = 場面、`"g:DKIM"` = 組み立て、それ以外は問題 ID）。取り返し問題も `seq` に差し込む。
- それ以外（stats・days・examDate・exams・ep.next・ep.results）は今のまま。

## 残すもの・変えないもの

- 後始末（復習）、模擬試験、事件ファイル、合格予測、試験日、連続日数、取り返し問題、「自信なし」、db 連携、1ファイル版、PWA。
- 後始末と模擬試験の問題画面も新しい見た目と演出にそろえる（ヒントは後始末だけ）。

## 役割分担
